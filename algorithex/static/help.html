Quick start (5 steps)

  1. Import candles for your exchange + symbol with a start date ≥ 2 months before your test window. Wait for finished.
  2. Write or pick a strategy in strategies/ (copy ExampleStrategy).
  3. Backtest it on your date range. Sharpe > 1 with 100+ trades is worth a look.
  4. Rule-test the entry (one route) — keep it only if p < 0.05.
  5. Monte Carlo (candles, 200 scenarios) — trust it if original ≈ median, distrust if original > best_5.

Candles & warm-up — read this first

Every run needs your test range plus 240 warm-up candles before the start date (indicator warm-up). How far back that is depends on your timeframe:

Timeframe240 candles ≈Safe import head-start
1m4 hours1 day
15m2.5 days1 week
1h10 days1 month
4h40 days2 months
1D240 days9 months
Rule of thumb: import starting 2 months before your start date (9 months if you trade the daily). Re-running an import is safe — existing candles are kept, only gaps are filled.

Backtest

  • Multiple routes allowed, but each exchange–symbol pair only once (use separate backtests per timeframe of the same symbol).
  • finish_date must be after start_date; use yesterday-or-earlier, never the future.
  • Trustworthy minimums: 100+ trades, tested across more than one period, fees left on.
  • Key metrics: Sharpe (risk-adjusted return), Calmar (return vs worst drawdown), win-rate with payoff ratio — win-rate alone means nothing.

Rule significance test (entry edge only)

Checks whether your entry timing predicts the next bar better than chance. Exactly one route. Use 1–2 years of data and n_simulations ≥ 2000.

p-valueVerdict
p < 0.05Entry edge supported — develop the strategy.
0.05 – 0.10Borderline — refine the signal or widen the window.
p > 0.10No reliable next-bar edge. (A profitable multi-bar strategy can still fail this and pass backtest/Monte Carlo.)
It does not test exits, stops, targets, sizing, or fees. Always report p_value with observed_mean, n_observations, n_simulations.

Monte Carlo (overfit detector)

  • Candles mode (default, 200 scenarios): resamples history — answers "was I lucky?".
  • Trades mode: only shuffles trade order — informs max drawdown only, never overfit. Leave off unless asked.
  • Compare on Sharpe: original ≈ median → good; original < median → great; original > best_5 → overfit, reject.
  • Then check the downside tail: if you can't stomach worst_5 drawdown, don't trade it.

Optimization

Expose knobs via hyperparameters(), keep the search space small (2–4 params), and always validate winners out-of-sample (different dates) — in-sample winners are guilty of overfitting until proven otherwise.

def hyperparameters(self):
    return [
        {'name': 'slow_period', 'type': int, 'min': 100, 'max': 250, 'default': 200},
        {'name': 'fast_period', 'type': int, 'min': 10, 'max': 100, 'default': 50},
    ]

Paper trading

Paper sessions start instantly with no plugin and are recorded as local-simulated. They track intent locally — real exchange execution is not wired yet, so validate with backtests + Monte Carlo first.

Strategy crash course

from algorithex.strategies import Strategy
import algorithex.indicators as ta
from algorithex import utils

class GoldenCross(Strategy):
    def should_long(self):
        return ta.ema(self.candles, 8) > ta.ema(self.candles, 21)

    def go_long(self):
        qty = utils.size_to_qty(self.balance * 0.05, self.price)  # risk 5%
        self.buy = qty, self.price

    def on_open_position(self, order):
        # exits belong here: bracket the open position
        self.take_profit = self.position.qty, self.price * 1.2
        self.stop_loss = self.position.qty, self.price * 0.9
  • Never use fixed quantities — size with size_to_qty / risk_to_qty.
  • On spot, should_short must return False; set exits in on_open_position.
  • No look-ahead tricks needed — the engine handles it. Don't shift indicators back a candle.

ErrorFix

Significance test demands one routeRemove extra/data routes — RST accepts exactly one trading route.
